# 三分钟视频脚本与分镜

前 2 分钟说明问题和需求，后 1 分钟说明解决方案和仓库。

## 0:00–0:15 开场

**画面**：黑底白字：“GPT 不一定不会做。很多时候，是它让你先替它做太多决定。”

**口播**：你有没有遇到过这种 GPT 或 Codex：答案看起来很完整，但真正的决定都被推回来了。模型说了很多话，事情却没有往前走。

## 0:15–0:45 交流成本

**画面**：左侧典型模板腔，标出“复述、前言、尾巴”。

**口播**：第一类问题是交流成本。先复述一遍需求，再给一段正式前言，最后补一句“如果你愿意我可以继续”。这些话不一定错，但很多时候没有增加信息。用户要先解码模型，才能找到真正的结论。

## 0:45–1:15 普通决定被退回

**画面**：打开交互页的“缺少低风险细节”场景。

**口播**：第二类问题是普通决定被退回。文件名、目录、测试框架，只要是低风险、可逆的细节，模型本来可以先选一个合理默认，跑通以后再改。结果却变成三四个确认题，用户被迫当项目经理。

## 1:15–1:45 果断与越权

**画面**：切到“准备发布”场景，左边是直接发布，右边是停在最终确认点。

**口播**：第三类问题更危险：有些模型为了显得果断，直接跳过证据和审批；另一些模型则连本地可逆操作都不做。真正需要的是一条清楚的线：普通选择直接承担，发布、删除、支付和权限变更停在最后一步。

## 1:45–2:00 需求收束

**画面**：四个词：结论前置 / 少绕路 / 证据可见 / 边界清楚。

**口播**：所以需求不是把模型变得更像朋友，也不是删掉所有谨慎。需求是四件事：结论前置，普通词，继续推进，证据和边界保留。

## 2:00–2:20 解决方法

**画面**：用户请求 → 决策层 → 执行与验证 → 表达层 → 结果。

**口播**：我把它拆成两个 Skill。decisive-execution 负责决策和执行：检查现状，选低后悔默认，做完一个可验证切片。human-first-execution 在上面增加表达层：第一句给结果，少复述，纠正后直接采用新约束。

## 2:20–2:40 交互数据

**画面**：打开 `demo/index.html`，切换模式和三个场景。

**口播**：仓库里有一个不依赖框架的交互页面。它用 1 到 5 的行为 rubric 对比首句给结果、普通决定承担、证据可见、纠正后继续和外部效果审批。这里是解释协议的目标数据，不是假装成模型跑分。

## 2:40–2:55 仓库介绍

**画面**：展示 `skills`、`comparison`、`demo`、`video` 目录。

**口播**：仓库里有两个 Skill 的源文件、参考矩阵、调研报告、对比数据、三分钟脚本和字幕。先在自己的对话样本上复测，再决定是否推广。

## 2:55–3:00 行动号召

**画面**：放大真实 GitHub URL。

**口播**：仓库地址放在简介里。先看 README，打开交互对比，再用你自己的对话样本复测。欢迎提交真实案例和反例。
